Chosen implementation shape

Separate manifests, explicit links

Next.js file-based manifest metadata wins over metadata overrides. The bean must remove that file-based manifest.

Before · global metadata 
<link rel="manifest" href="/manifest.webmanifest">

{
  "short_name": "Sans Souci",
  "start_url": "/fr",
  "display": "standalone"
}
After · route-specific metadata 
/checkin head:
<link rel="manifest" href="/checkin.webmanifest">

{
  "short_name": "Check-in",
  "start_url": "/checkin",
  "scope": "/checkin",
  "display": "standalone"
}
Scratch probe result

Next.js 16.2.6 confirms this shape

A disposable copy of this repository was built and probed. No project file changed.

  • Delete src/app/manifest.ts because file-based manifest metadata overrides config metadata.
  • Move the current public-site manifest to public/manifest.webmanifest.
  • Add public/checkin.webmanifest with start_url /checkin and scope /checkin.
  • Set metadata.manifest explicitly in the six sibling root layouts.
  • The probe emitted exactly one correct manifest link on /checkin, /fr, /queue, /clientportal, /subscription, and /admin/login.
  • Both public manifest files served Content-Type application/manifest+json.
Regression boundaries

Public website

Other kiosk pages

/queue, /clientportal, /subscription, and /admin keep the main manifest link in this bean.

Existing icon warning

Reinstall is required

The user must delete the old iPad icon and add it again after deployment. iPadOS does not reliably mutate the existing icon.

Acceptance signals

What proves the fix

  • /checkin emits exactly one manifest link, and it points to /checkin.webmanifest.
  • /checkin.webmanifest serves application/manifest+json with start_url /checkin and scope /checkin.
  • /fr emits exactly one manifest link, and it points to /manifest.webmanifest.
  • /manifest.webmanifest keeps start_url /fr and display standalone.
  • On iPadOS 26.3.1, a newly added icon cold-opens /checkin in standalone mode.
